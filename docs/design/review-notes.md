# Lab design guideline · 设计评审草案

Navers lab · Einsia · v0.1 · 待设计评审 · 2026-11-27

**定位：有编辑判断的研究出版物。** 读者先看懂研究问题，再看到证据，最后进入论文、代码或可复现的实验。页面的辨识度来自真实研究内容、排版和稳定的品牌，而不是不断更换的视觉主题。

本文件供设计评审，提出 Lab 内容页面的统一视觉方向。讨论范围包括首页、Research、About、项目介绍、排行榜、方法详情、案例和轨迹浏览页，以及独立 HTML 子站。正文以中文说明设计建议；界面示例沿用线上英语内容。

**当前状态：待设计评审。** 以下原则、尺寸、颜色和模板均为提案，不代表已经确认的项目标准。评审后再根据反馈修订，确认定稿后另行整理执行规范。

## 评审重点 {#review-scope}

1. **视觉方向：** 暖纸色、深绿色、衬线标题是否适合作为所有 Lab 内容页的共同基础。
2. **统一程度：** 页头、字体、按钮与内容宽度统一到什么程度；研究图表与媒体保留哪些项目差异。
3. **信息层级：** 标题、摘要、证据与资源入口的顺序是否清晰，文字密度和留白是否合适。
4. **组件与模板：** 四类页面是否覆盖实际内容，是否需要补充特殊项目页或其他变体。
5. **响应式：** 在示例上切换 1280px 与 390px，检查标题换行、导航、图表与表格的阅读体验。

建议先看颜色和字体示例，再看四类整页模板，最后讨论细节约束。评审意见可按章节名称或组件名定位；具体参数可以根据设计反馈调整。

## 01 · 从现有 Lab 收敛 {#f-context}

检查日期：2026-11-27。线上抽样包括 `/`、`/research/`、`/visual-cipher-bench/`、`/frontier3d/`、`/embodiedevo/`、`/workflowarena/`、`/robo-universe/`；同时检查对应仓库样式。此处是抽样观察，不代表所有页面的完整审计。

- 首页和 Visual Cipher Bench 已采用暖纸色、深绿文字与 Georgia 标题，可以作为品牌基线。沿用“问题 → 证据 → 结果”的信息顺序，不照搬其所有尺寸和细节。
- 在同一次 1000px 视口检查中，Visual Cipher Bench 的 H1 为 Georgia 60px，EmbodiedEvo 为 Inter 75px，Frontier3D 为 Georgia 72px 且叠在视频上。标题系统和首屏结构缺少共同约束。
- WorkflowArena 与 RoboUniverse 的页面底色为 `#f7f5ee`，主站为 `#f4efe4`。差别虽小，多处独立定义会持续积累。
- `src/styles/pptbench.css` 单设橙色交互强调色，`phys-last-exam.css` 覆盖全局 accent，EmbodiedEvo 多处使用橙、蓝专属控件。研究系列配色与站点交互色混在一起。
- `public/workflowarena/` 与 `public/robo-universe/` 的静态页面不会自动继承 Astro 的 Layout。仅修改主站 CSS 无法完成统一。

参考 Bowen 的 AgentGit 文件，借鉴“原则 → token → 组件 → 模板”的组织方式。本提案保留 Lab 自身品牌与研究内容的阅读密度。

## 02 · 设计原则 {#f-principles}

- **内容承担视觉中心。** 每节解决一个阅读问题。优先用标题、段落、图表和留白组织内容；容器只在表达独立对象或交互边界时出现。
- **一个 Lab，多个研究对象。** 页头、页脚、标题、资源链接、表格和交互状态保持一致。项目的差异来自任务实例、方法图、结果图与媒体。
- **先讲清楚，再强调。** 标题指向研究对象；摘要包含问题、方法或结论。数字必须同时有口径。首屏不要求凑齐四项 KPI。
- **证据比承诺醒目。** 论文、数据、代码和真实案例有明确入口。贡献陈述连到证据，局限有可见位置。
- **稳定胜过热闹。** 阅读时不移动布局，不用持续动画争夺注意力；可交互部分有明确控件和状态。
- **精简不是缩小。** 删除重复装饰，保留足够字号和点击面积。不能用 8–11px 标签塞下更多内容。

## 03 · 去除模板化的 AI 味 {#f-anti-patterns}

下列是可检查的行为规则，不以“高级感”“科技感”等主观词验收。

- 不使用渐变标题、霓虹光晕、装饰性网格、粒子、玻璃卡片、随机星星或 emoji 图标。图表表达连续数值时可使用带色标的连续渐变。
- 不用全屏视频或 100vh hero 作为项目默认首屏。视频与 3D 是可观看的证据，放在摘要和资源链接后；页头和主要文字放在稳定的纸色表面。
- 不把每个段落包成卡片，不用固定三列图标卡片表达所有贡献。连续论述用正文，比较用图表，独立可点击对象才使用列表或卡片。
- 不默认居中整页，不手动插入 `<br>` 拼造标题形状，不给标题每个词上色，不按页发明字体组合。
- 不使用自动滚动案例墙、入场飞入、数字计数、视差、悬浮上移或发光 hover。方法步骤可由读者主动播放或切换。
- 不写没有依据的 “revolutionary”“unlock the future”“redefine what is possible”“业界领先”“颠覆”。保留正式项目名和真实论文标题；新增描述改为对象、方法和证据。
- 不用假终端、假日志、假实时状态装饰内容。只有真实且可解释的轨迹、代码和运行反馈才能进入页面。

**文案示例：** “Redefining the future of visual intelligence” 改为 “Can coding agents discover rules hidden in images?”；进一步用 “40 original puzzles; best reported accuracy 26.7%” 表达实验范围与结果，并链接 Visual Cipher Bench 的论文与评测口径。这些数字只属于该研究，不移植到其他项目。

## 04 · 色彩与主题 {#f-colour}

品牌取自 `src/styles/global.css`：paper `#f4efe4`；paper-2 `#ebebe0`；paper-3 `#e3e8db`；ink `#273d32`；ink-2 `#5d6e60`；accent `#3b5545`；accent-hover `#192c22`；on-dark `#f5f1e8`。

- `--lab-bg` 用于页面；`--lab-surface` 用于代码、表头和中性提示；`--lab-selected` 用于选中行或筛选。
- `--lab-text` 用于标题与正文；`--lab-muted` 用于辅助文字，本版统一为稍深的 `#56675a`，保证在 selected 表面也有足够对比度。旧 `ink-3/4/5` 不用于承载必要的小字号信息；元数据也需要可读对比度。
- `--lab-accent` 用于链接、焦点、激活标记和主要操作；`--lab-on-accent` 用于深绿填充上的文字。正文链接默认带下划线；导航和按钮靠布局与形态识别。
- `--lab-border` 用于分区细线；输入框使用对比更强的 `--lab-control-border`。分隔线不是输入框轮廓的替代。
- 白色 `--lab-figure-bg` 仅用于需要白底的论文图、截图和图表。媒体可用 `--lab-media-bg` 深底，不能扩散成整页主题。
- 状态用 success、warning、danger 语义色，同时显示明确文字或符号。失败不只显示红点，成功不只显示绿色。
- 默认且本版唯一完整主题为浅色。浏览器偏好深色时仍使用浅色；未来深色模式须先补齐全套语义 token、图表和媒体规则，不由某个项目自行反色。

参考 token 使用 `--lab-*` 前缀。已有品牌 token 通过 `var(--color-…, fallback)` 映射，避免与 Tailwind 全局名称冲突。独立 HTML 使用相同 fallback；CI 或人工审查应核对与主站品牌值一致。

## 05 · 字体与文字层级 {#f-type}

- 英文标题：Georgia，回退 Times New Roman、serif；中文标题回退 Songti SC、Noto Serif CJK SC、SimSun。H1/H2 使用 700，标题不使用斜体。
- 正文、导航、按钮、图表标签：项目已安装的本地 Inter Variable，回退系统无衬线和 PingFang SC / Microsoft YaHei。不额外请求 Google Fonts。离线单文件示例使用系统回退；线上由 Layout 加载本地 Inter。
- 代码、任务 ID、文件路径：系统 monospace。数值列使用 Inter + `tabular-nums`，不为“技术感”把说明文字变成等宽字体。
- 项目 H1：桌面 48/56，手机 36/44；站点首页专用 display：桌面 60/68，手机仍为 36/44。长项目名自然换行。
- H2：32/40，手机 28/36。H3：24/32，手机 22/30。列表标题为 22/30；控件区的小标题使用无衬线 16/24、600。
- 长文正文：18/30，手机 16/28；常规说明 16/26；界面与元数据 14/22；图注 14/22；只有次要的紧凑数据标签可用 12/18，不能再小。
- 正文列最大 720px；英文目标每行约 60–80 字符。中英混排都不两端对齐；中文不加英文式字距；正文不压缩字距。
- 每页恰好一个 H1。H2 表示章节、H3 表示章节内小节，不为字号跳过语义层级。

## 06 · 布局、间距与响应式 {#f-layout}

- 标准外框最大 1120px，包含左右内边距；宽结果或探索页可使用 1280px 外框。正文最大 720px，图表和媒体可占满外框内部。页头、H1、章节、页脚沿同一左边线对齐。
- 断点只使用 768px 和 1024px。小于 768：左右 20px；768–1023：24px；1024 及以上：32px。窄屏由内容自然增长，不固定段落或 hero 高度。
- 全局页头最小高度 64px；一级导航为 Home、Research、About、Einsia Home。小于 1024 折叠为可操作的 Menu，展开后所有入口可访问，不直接隐藏导航。
- 项目页从返回 Research 的面包屑开始；局部导航位于项目标题/摘要/资源组之后。当前项目所属的 Research 在全局导航中保持当前分区语义。
- hero 顶部间距桌面 64px、手机 40px。标题到摘要 24px；摘要到元信息 16px；资源组距上方 24px。下方正文/证据 40px 起。
- 章节间距桌面 64px、手机 40px；章节标题到正文 16px；正文到图表 24px；段落间 16px。采用 4、8、12、16、20、24、32、40、48、64、80px 的间距尺度。
- 双栏为 `minmax(0, 1fr)` + 240px 目录或参数栏，间距 40px；小于 1024 合并为一列。目录转换成折叠目录，筛选置于结果前。
- 在 390px 宽度下整页不横向溢出。仅宽表格、代码块、局部 tabs 可在自身区域滚动；不要用 `body { overflow-x: hidden }` 掩盖布局错误。
- 圆角：4px 小标签，6px 按钮/输入，8px 媒体框/独立面板，12px 弹窗。胶囊只用于人的头像或确有状态意义的标签，普通资源链接保持矩形圆角。
- 结构线 1px；卡片、按钮、数据面板无投影。只允许弹窗/浮层使用共享 overlay shadow。

## 07 · 研究图表与证据 {#f-evidence}

- 图表必须有可见标题、指标和单位、数据来源、实验条件；存在坐标轴时标出轴名称与单位，多个系列有图例，图注说明结论或局限。没有坐标轴的流程图标明步骤和方向。
- 明确区分 task、run、model、configuration；精度、成功率、耗时和成本不可混用。百分比增量用 percentage points / pp，倍数写清基线。缺失值用 “— / Not reported”，不转成 0。
- 排名显示评测集、版本/日期（有真实来源时）、指标方向 ↑/↓、模型配置和样本口径。有置信区间就展示；没有就不编造。不同预算或协议的结果分组或明确注明不可直接比较。
- 默认单系列深绿；基线灰绿。多系列按稳定顺序使用 `plot-1…4`，再以线型、点形、直接标注辅助识别。一个语义在同一项目中颜色保持不变。
- 论文已有明确系列配色时可保留；在代码中定义有语义的 `--plot-*` 局部 token 并注明来源。该例外不适用于按钮、页头、导航、正文链接。
- 条形图从零开始；折线图如截断坐标要显式说明。不用 3D 饼图、面积膨胀或不同尺度制造提升。热力图使用有数值标注的单调色标，发散色标须说明中点。
- 论文图、失败截图、3D 渲染和视频保留比例与内容，不为了统一色调加滤镜、不把证据裁成装饰封面。图片必须有 alt，图注保留图号/来源；截图中的小字不可代替可访问正文。
- SVG 内文字至少 12px；手机不能把整张桌面图缩到不可读。必要时改成纵向小图、提供可放大原图与等价数据表。
- 对视频用 poster、controls、`preload="metadata"` 或 `none`；默认点击播放。讲述信息的视频提供字幕或文字等价内容。3D 仅在用户激活或进入视口后加载，并有静态预览与失败说明。

## 08 · 文案、命名与资源 {#f-copy}

- 页面语言保持一致。默认英语；中文版本用准确对应的术语。品牌正文保留当前字标 “Navers lab”，正式署名按真实来源，代码路径不作为对外项目标题。
- 英文 UI 使用 sentence case。正式论文题目、项目名和缩写维持官方写法；不要机械改写专名。
- 摘要通常 1–3 句，回答研究什么、怎么做、发现什么。一个段落围绕一个观点。内容组织以研究需要为准，不为模板凑三个卖点或四个数字。
- 资源顺序固定：Paper → Code → Dataset（存在时）；项目内导航用 Results、Tasks/Cases、Method、Citation。已发布 arXiv 可标为 Paper，并在辅助文字说明 arXiv。
- 导航使用明确名词；执行动作使用具体动词：Copy citation、Reset filters、Download data、Retry loading。避免 Start your journey、Explore more 等缺少对象的标签。
- 没有发布的资源显示 “Paper forthcoming” 等普通状态文字并解释，不生成 `href="#"`、无响应按钮或虚假下载。
- 日期使用 `Nov 27, 2026` / `2026 年 11 月 27 日`，保留原始时间和版本来源；不用构建时间冒充数据更新时间。
- 中文使用全角标点，与 Latin 和数字间留空格；中文不斜体。术语：benchmark 基准评测、task 任务、run 单次运行、trajectory 轨迹、configuration 配置、success rate 成功率。
- 错误说明“发生了什么 + 能做什么”，例如 “Results could not be loaded. Retry loading or open the published table.” 不写责怪用户的语气，不用夸张感叹号。

## 09 · 共享页头与项目开场 {#c-header}

**Site header：** 复用现有标志 SVG 和字标，不重新绘制、不按项目重着色。纸色底、1px 底线、无模糊玻璃。品牌链接回首页，当前栏目加字重/下划线并设置 `aria-current`。页脚包含 Lab 归属、Research 和真实公共资源链接。

**Project header：** Research 面包屑 → H1 项目名称 → 研究问题/摘要 → 作者/机构/真实年份 → 资源组 → 可选 2–4 个有口径的事实。默认左对齐。无资料的作者/年份不补猜。

**Resource group：** 一组内至多一个深绿主链接，通常为 Paper；其余 outline 或文本。长文末尾可重复必要资源，但不在每节增加 CTA。小屏换行，不能截掉文字。

**Project nav：** 单层文本导航 + 当前项下划线。链接负责跳页或锚点；原地切换面板才用 ARIA tabs。最多保留读者需要的主要入口，更多内容放目录；锚点偏移应避开 sticky header。

## 10 · 按钮、表单与标签 {#c-controls}

- 导航用 `<a>`，动作/切换用 `<button type="button">`，不以可点击 div 替代。按钮至少高 40px；触摸环境高 44px；独立图标按钮始终 44×44px。
- primary 为深绿底浅文字；secondary 为纸色底加边线；quiet 为文本。危险填充只用于明确的危险确认，不用于普通结果状态。
- 每个控件定义 default、hover、focus-visible、active、disabled；pending 用明确动词进度文字，阻止重复动作且保留宽度。
- 输入、搜索和 select 高 44px，边线为 control-border；有持久 label，placeholder 只提示格式。错误通过 `aria-invalid` 与 `aria-describedby` 关联，保留用户输入。
- 可选项说明和选中状态不能只靠颜色。筛选后显示结果数量；Reset filters 恢复默认值；URL 可表达的筛选应支持刷新和分享。
- 图标优先用项目现有 `astro-icon` / Boxicons，一个页面统一线条风格，常规 16px 或 20px；不要同时引入多套图标库。纯图标操作同时有 accessible name 和可见 tooltip。
- 标签只显示领域、版本或状态等事实，采用中性底 + 文字。不用随意分配的彩虹分类，不用 emoji 作 UI 图标；研究素材自身的符号保持原样。

## 11 · Research 列表与事实条 {#c-research-row}

Research 默认采用可扫描的纵向项目行：项目名 → 一句研究描述 → 类别/真实发布时间 → 资源链接。存在有辨识力的真实研究缩略图时放左侧或右侧，比例统一、内容不裁损；手机置于标题上方或省略非必要缩略图。

项目名为主要入口；同一行的 Paper、Code 独立可点，不把整行包成一个链接后再嵌套链接。行间以留白和细线分隔，hover 只改变文字或背景。无需给每个项目独立的品牌底色。

事实条使用 `<dl>`：`dt` 是指标名称，`dd` 是值。每个值同时有单位或范围；手机 2 列或 1 列，长标签换行。它是摘要，不代替结果表。

## 12 · 结果表、图注与引用 {#c-results}

**Results table：** 使用原生 table、caption、thead、tbody、行/列表头 scope。文字左对齐，数字右对齐并用等宽数字；每列保留一致的小数精度。排序按钮置于表头，通过 `aria-sort` 表达状态；默认顺序与主指标一致，排序后完整行一起移动。

最高分可加粗；本机构模型可加说明标记，但不得改变排序和颜色尺度。缺失值不能因排序跳成最高或最低真实分数。窄屏表格保持局部滚动，标明可横向滚动，焦点进入滚动容器后可用键盘操作。

**Figure：** 统一为 figure + 图表/图片 + figcaption。图注 14/22，以“Figure N. 结论/说明”开头，接来源和协议；不要重复整段正文。必要的交互说明放图前，来源放图后。

**Citation：** 使用完整真实 BibTeX；pre/code 局部滚动。Copy citation 成功后以 `role="status"` 提示 Copied；剪贴板权限不可用时选择可见文本，提示手动复制，不能伪报成功。长文本不撑破容器。

## 13 · 案例、媒体与轨迹 {#c-explorer}

案例探索器按“选择对象 → 看结果 → 查过程”排列。筛选在内容前，任务名和条件可见，结果与成功/失败文字紧邻媒体。卡片只用于可独立打开的案例，默认 2–3 列，手机单列。

视频、代码和反馈共享任务/运行 ID；切换案例要一起更新，避免上一案例的代码留在新视频旁。视频角度、步骤和模型标签用真实名称。并排比较使用相同案例、时间与画幅；不同条件显式说明。

轨迹页桌面可用媒体 + 代码/事件双栏；手机按任务说明、媒体、结果、过程的顺序叠放。代码不默认无限展开，提供展开完整内容和下载入口。时间线有步骤编号或时间，颜色不作为唯一编码。

状态必须区分：未选择、加载中、无筛选结果、资源未发布、媒体加载失败、任务评测失败。评测失败是研究数据；媒体请求失败是界面状态，两者不可混写。

## 14 · 状态、反馈与动效 {#c-states}

- **Loading：** 保留区域尺寸与表头，`aria-busy="true"`；旁边显示 “Loading results…” 或 “Loading media…”。静态研究页面不人为添加加载动画。
- **Empty：** “No cases match these filters.” + Reset filters。尚未发布写 “Results have not been published.”，不显示伪造 0 分。
- **Error：** 说明资源失败，提供 Retry loading 或真实的论文/数据后备入口。保留筛选和上下文；失败提示使用 alert，非紧急更新使用 status。
- **Selected：** 文本加粗、下划线或明确标记 + selected 底色；不要只让边框变橙色。禁用项使用原生 disabled 并给出可见理由。
- **Disclosure：** 优先 details/summary。Dialog 有标题、关闭按钮、Escape、焦点锁定和关闭后焦点归还。内容放大不能只靠鼠标点击图片触发。
- 颜色过渡 120ms；面板开合 180ms；无循环装饰。`prefers-reduced-motion: reduce` 下关闭过渡、平滑滚动和自动演示，方法步骤仍可手动操作。

## 16 · 可访问性与性能 {#f-accessibility}

- 普通文字与背景至少 4.5:1，大号文字至少 3:1；必要的控件边界与图形至少 3:1。焦点使用 2px 深绿 outline + 2px offset，不能只显示很淡的阴影。
- 提供 Skip to content；合理使用 header、nav、main、article、section、footer。图标装饰 `aria-hidden`，每个操作有名称。每个 iframe 有明确 title。
- Tab 能到达并操作菜单、筛选、排序、播放器、复制和弹窗；焦点顺序与视觉顺序一致。ARIA tabs 需支持方向键与 Home/End，否则用普通按钮或导航链接。
- 支持 200% 缩放、390px 手机、长项目名和中英混排。焦点与锚点不被 sticky 元素遮住；必要文字不依赖 hover 才可见。
- 主要正文、标题、资源链接与核心研究结论在无 JavaScript 时仍可读。交互增强失败不应留下空白首页。
- 图片设置 width/height，首屏关键图不 lazy-load；后续图按需加载。避免把全部案例 JSON、视频和 3D 引擎放进初始包；静态内容使用 Astro 默认静态渲染。
- 只在实际需要的组件加载脚本。以页面实测检查 LCP、CLS 和交互反馈；性能预算例外说明资源用途与加载方式，不用未经测量的速度承诺。
